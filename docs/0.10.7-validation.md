# 0.10.7

Both VPN timers use an upward digit roll with a short blur, based on `Screenrecording_20261119_203357.mp4`. The reference transition takes roughly 300 ms; the implementation takes 320 ms with a finite easing curve. Android shares one animation progress across changed digits, so minute/hour carries stay synchronized. A new value cancels the previous transition instead of queuing it. First render, disconnection and lightweight mode display the value immediately. Android versions before API 31 retain the slide/fade without blur. Desktop uses the same timing and respects lightweight/reduced-motion settings.

Android notifications show the server in the content title and connection state beneath it. The operating system still controls its application identity header. Shared Pause/Resume/Disconnect actions run through a short-lived private foreground control service, including when the app is in the background. Pause fully disconnects the transport and releases the VPN interface. It leaves a regular stopped notification without a foreground service, network watchers or wake locks. Resume uses the saved account configuration and selected server. Opening the app while paused skips automatic connection; manual connection or Disconnect clears the paused notice. Failed resume retains a retry action. Stale Pause actions from the other VPN are ignored.

The release also includes the unreleased 0.10.6 changes documented in `0.10.6-validation.md`.

## Validation

- Android: 39 unit tests, signed ARM64/ARMv7/universal packages; all signatures verified.
- Desktop: Go tests passed; JavaScript syntax check passed; five platform packages built.
- Linux x64: native GTK/WebKit startup and local API shutdown passed under Xvfb.
- Vivo: installed release build; primary notification Pause/Resume tested, server and status text verified. Opening the app while paused kept the VPN stopped.
- Vivo reserve: Pause left zero active app service records and no WDTT native process; Resume restored all 30 streams. The notification showed the server and Connected/Stopped states correctly.
- A 68-second recording on Vivo covered the minute carry `00:59 → 01:00`. Changed digits moved together and settled before the next second.

macOS and Linux ARM64 are cross-compiled; physical-platform testing was not performed.
