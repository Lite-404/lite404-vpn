# 0.10.6

WDTT now owns TURN allocations independently of server sessions. `SWITCH` prepares another DTLS/WireGuard generation on the existing allocations and a separate local UDP port. The app acknowledges the applied configuration before the old generation leaves the active path. A failed switch restores the previous configuration. Up to two inactive server generations stay warm for 60 seconds; expiry and Stop close their sockets and goroutines. A network or account change still requires rebuilding the transport. Changing the public exit IP cannot preserve arbitrary existing TCP connections.

Android and desktop share this transport. Android updates the existing WireGuard tunnel object or reuses the sing-box TUN; desktop keeps its TUN helper alive. Concurrent desktop server selections no longer fall through to a full disconnect.

Primary Android VPN saves a private recovery checkpoint and distinguishes explicit Stop/revocation from system restart. Network recovery errors retry while retaining the TUN. The surviving main process also restores an observed working primary connection if its separate core process disappears. Recovery is bounded and does not enable VPN on a cold launch when automatic connection is disabled.

Subscription refresh uses Android JobScheduler approximately every two hours, plus a refresh on return to the app. Desktop refreshes periodically and on focus. API renewal metadata reports queued paid periods separately from the current quota period; existing authorization expiry is unchanged. Server implementation is in the workspace's `lite404/wdtt/l4wdtt/subscription.py` and is deployed in `lite404-api.service`.

Journal segments use the shared dock spring/glass renderer without clipping the expanded lens. Resting corner radii match the container.

## Validation

- Android unit tests and signed ARM64/ARMv7/universal builds.
- Go transport and desktop tests; Linux race detector on allocation reuse, switching, expiry and cleanup.
- Encrypted loopback TURN/DTLS tests with 1 and 30 allocations: A → B, rejected switch, return to A, no extra allocations.
- Live desktop: all three countries, 30 streams, unchanged process, successful internet checks. First switches took about 5–6.5 seconds; warm returns about 0.06–0.07 seconds in this network.
- Desktop transport remained at 30 streams for 1,316 seconds with a stable handle count and terminated cleanly.
- Vivo: signed update installed, queued renewal displayed, expanded journal glass observed; 30-stream country change and return preserved the client process.
- Vivo core-process crashes were injected while the main process stayed alive. Recovery completed in about 2.8 seconds with the app visible and 1.12 seconds with it in the background; the main PID did not change. Explicit Stop kept the VPN service stopped.
- Final installed build registered a persisted two-hour subscription job with a 15-minute scheduling window; a forced job invocation completed successfully.
- Linux x64 package opened its native GTK/WebKit window and completed the local API startup/shutdown check under Xvfb.

macOS and ARM Linux builds are cross-compiled; those physical platforms were not tested.
