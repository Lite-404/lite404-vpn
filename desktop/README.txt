Lite 404 VPN — самостоятельный клиент для Windows, macOS и Linux

Программа открывает СОБСТВЕННОЕ окно с боковым меню. Браузер для работы
приложения не запускается. Интерфейс встроен в системный WebView: WebView2
на Windows, WebKit на macOS и GTK/WebKitGTK на Linux. Движок VPN и интерфейс
работают в одном приложении, без отдельного браузерного профиля.

Windows — распаковать архив и запустить «Lite404 VPN.exe».
macOS — переместить «Lite404 VPN.app» в «Программы» и открыть.
Linux — распаковать tar.gz и запустить lite404-vpn/lite404-vpn.

Крестик окна сворачивает клиент, сохраняя соединение. Трей позволяет открыть
окно, подключить основной или резервный VPN, отключиться и выйти.
Повторный запуск возвращает существующее окно. На Linux при отсутствии
области уведомлений окно остаётся доступно в панели задач. Кнопка «Выйти»
останавливает VPN и завершает приложение.

Windows 10/11: требуется Microsoft Edge WebView2 Runtime (обычно установлен).
Linux: GTK3 и WebKitGTK 4.1; для трея — поддержка AppIndicator в окружении.
Ubuntu/Debian: libwebkit2gtk-4.1-0, libayatana-appindicator3-1.
macOS-сборки не подписаны и не нотарифицированы Apple.

Вход и настройки сохраняются в прежних папках:
Windows: %APPDATA%/Lite404
macOS: ~/Library/Application Support/Lite404
Linux: ~/.config/Lite404

Основной VPN — sing-box-extended. Резервный — core/wdtt-client и WireGuard
в том же ядре, 1–30 потоков. Есть HTTP GET, ICMP и TCP-пинг, свои и готовые
списки для обоих VPN, выбор процессов, темы, AMOLED, масштаб текста,
облегчённый режим и раздельные журналы (по умолчанию отключены).

Режим выбирается в Настройки → Подключение → Режим VPN.
TUN перехватывает трафик приложений через виртуальный сетевой интерфейс.
При подключении ОС запрашивает разрешение администратора. Интерфейс программы
остаётся обычным пользовательским процессом; отдельный помощник с правами
администратора создаёт TUN и пересылает трафик в локальное ядро. При отключении,
выходе или потере связи с программой помощник убирает свои маршруты и DNS.
Windows: официальный подписанный wintun.dll уже включён, держите его рядом
с EXE. Linux: нужен pkexec (polkit) и /dev/net/tun. macOS: системный utun,
пароль администратора запрашивается через системное окно.

Системный прокси доступен как альтернативный режим без повышения прав:
HTTP 127.0.0.1:10809, SOCKS5 127.0.0.1:10808. В этом режиме приложения,
игнорирующие системный прокси, автоматически не перехватываются.
Правила выбора процессов действуют в обоих режимах. В TUN локальный трафик
к ядру и транспорт WDTT исключены из перехвата, чтобы избежать петли.
DNS в TUN перехватывается и отправляется зашифрованным DoH-запросом напрямую.
Настройки соединения применяются при следующем подключении.

WDTT использует тот же Go-код, что Android: 30 потоков, группы по 10 без
искусственных пауз между группами, до 15 параллельных DTLS-рукопожатий,
краткосрочный кэш проверенных TURN-учётных данных, обработка лимитов VK,
обновление устаревших соединений и освобождение сокетов при остановке.
Смена физической сети перезапускает транспорт после стабилизации адреса;
создание собственного TUN не вызывает повторных перезапусков.
Фактическое время подключения зависит от сервера, VK и сети.

Сборка всех платформ из desktop/, Go 1.27:
go run ./pack 0.10.5 dist
Windows x64, macOS Apple Silicon / Intel, Linux x64 / ARM64.
Окно и трей — Wails 3.1.0. Для кросс-сборки macOS и Linux используется
экспериментальный backend purego; перед релизом нужна проверка на устройствах.

127.0.0.1:47404 обслуживает только локальное API управления, не интерфейс.
Для тестов без окна: LITE404_NO_BROWSER=1. Обычный запуск всегда создаёт окно.
